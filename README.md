# 놀이게임

제시어로 하는 놀이 두 가지를 진행해 주는 아이패드용 웹앱입니다.
아이패드 홈 화면에는 **놀이게임**이라는 이름으로 설치됩니다.

| 게임 | 어떤 놀이인지 |
|---|---|
| **몸으로 말해요** | 초등학교 2~5학년 아이들과 하는 제스처 게임. 스케치북 대신 앱이 제시어를 보여줍니다 |
| **라이어 게임** | 한 명만 제시어를 모른 채 아는 척하고, 나머지가 그 사람을 찾아내는 놀이 |
| **술래 정하기** | 손가락을 올리거나 이름을 넣어서 술래를 뽑는 도구 |

두 게임은 **같은 제시어 데이터**를 함께 씁니다. 제시어를 늘리면 양쪽에서 다 쓰입니다.

인터넷 없이 돌아가고, 로그인이나 서버가 필요 없습니다. 모든 기록은 아이패드 안에만 저장됩니다.

## 아이패드에 설치하기

한 번만 해 두면 다음부터는 앱처럼 아이콘을 눌러서 바로 열립니다.

1. **사파리**로 앱 주소를 엽니다. 크롬이 아니라 사파리여야 합니다.
2. 화면 위쪽의 **공유 단추**(네모에 위쪽 화살표)를 누릅니다.
3. 목록을 아래로 내려 **홈 화면에 추가**를 누릅니다.
4. 이름을 확인하고 오른쪽 위 **추가**를 누릅니다.
5. 홈 화면에 생긴 아이콘을 누르면 사파리 주소창 없이 **전체 화면**으로 열립니다.

설치한 뒤 앱을 한 번 실행하면 필요한 파일이 아이패드에 저장돼서, 그다음부터는
**비행기 모드나 인터넷이 안 되는 곳에서도** 게임을 끝까지 할 수 있습니다.

### 게임하기 전에 확인할 것

- **가로로 들고** 쓰면 제시어가 가장 크게 보입니다. 세로로 써도 동작합니다.
- 아이패드 옆면의 **무음 스위치**가 켜져 있으면 효과음이 나지 않습니다.
- 게임 중에는 화면이 저절로 꺼지지 않습니다.
- **화면 회전 잠금**을 걸어 두면 아이들이 기기를 돌려도 화면이 뒤집히지 않습니다.

## 몸으로 말해요

설명하는 사람이 아이패드를 자기 쪽으로 들고 화면의 제시어를 확인한 뒤 몸짓이나 말로 설명하고,
맞히는 사람은 화면을 보지 않습니다.

### 팀 대항전

팀을 2~4개로 나누고 번갈아 설명합니다. 팀마다 제한 시간이 따로 주어지고,
시간 안에 많이 맞힌 팀이 이깁니다.

### 릴레이전 (단체)

편을 가르지 않는 **협동전**입니다. 참가자 2~8명이 하나의 팀이 되어,
**제한 시간 하나를 다 같이 나눠 씁니다.**

- 각자 정해진 개수만큼 맞혀야 합니다.
- 시간 안에 전원이 자기 몫을 채우면 **통과**입니다.
- 기기를 다음 사람에게 넘기는 동안에는 시간이 멈춥니다.
- **패스**는 아직 몫이 남았을 때 누르면 제시어만 바뀌고, **마지막 한 개가 남았을 때**
  누르면 그 제시어를 그대로 다음 사람이 이어받습니다. 못 채운 몫은 남아서 다시 돌아옵니다.

### 공통 설정

주제(복수 선택), 난이도(쉬움 / 어려움 / 섞기), 설명 방식(몸으로만 / 말 설명 허용),
제한 시간, 패스 허용 횟수, 힌트 사용 여부를 게임 시작 전에 고릅니다.

**주제는 늘 아무것도 선택되지 않은 상태로 열립니다.** 그날 할 주제만 골라 쓰라는 뜻이고,
나머지 설정은 지난번에 쓰던 값을 그대로 기억합니다. 라이어 게임도 마찬가지입니다.

설정 화면 아래쪽에 **이 조건으로 몇 판까지 같은 제시어가 안 나오는지** 미리 알려줍니다.

## 라이어 게임

3~10명이 기기 하나를 돌려 가며 하는 놀이입니다. 사회자가 따로 없어도 앱이 진행을 맡습니다.

### 진행 순서

1. **제시어 확인** 기기를 한 사람씩 넘겨받아 화면을 **꾹 누르고 있는 동안에만** 내용을 봅니다.
   한 명에게만 '당신은 라이어입니다'가 뜨고, 나머지는 제시어를 봅니다. 손을 떼면 바로 가려집니다.
2. **설명** 앱이 정한 순서대로 한 명씩 제시어를 돌려서 설명합니다.
   라이어는 다른 사람 설명을 듣고 제시어를 짐작해서, 아는 척 자기도 설명해야 합니다.
   너무 정확히 설명하면 라이어에게 답을 알려 주는 셈이고, 너무 모호하면 자기가 의심받습니다.
3. **투표** 정해진 바퀴를 다 돌면 라이어로 의심되는 사람에게 투표합니다.
4. **결과** 지목한 사람이 라이어였는지 시민이었는지부터 크게 알려 줍니다.
   라이어를 맞혔더라도 그 라이어가 제시어를 알아맞히면 뒤집어서 라이어가 이깁니다.
   시민을 지목했으면 아래 설정에 따라 한 번 더 기회를 얻거나 그대로 라이어가 이깁니다.

### 설정

| 항목 | 고를 수 있는 것 |
|---|---|
| 참가자 | 3~10명, 이름을 직접 넣을 수 있음 |
| 주제·난이도 | 몸으로 말해요와 같은 방식. 주제를 여러 개 고르면 라이어가 더 어려워집니다 |
| 설명 바퀴 수 | 1~3바퀴 |
| 한 사람 설명 시간 | 제한 없음 / 15초 / 30초 / 45초. 시간이 다 돼도 저절로 넘어가지 않고 소리로만 알려 줍니다 |
| 라이어에게 주는 정보 | 주제까지 알려주기 / 아무 단서 없이 시작 |
| 투표 방식 | 앱으로 비밀 투표(기기를 돌려 가며 한 명씩) / 손으로 지목하고 결과만 입력 |
| 엉뚱한 사람을 지목하면 | 바로 라이어 승리 / 설명 없이 바로 다시 지목 / 설명을 한 바퀴 더 돌고 재투표. 뒤의 두 가지는 판마다 한 번만 |

라이어는 언제나 한 명입니다. 앱 비밀 투표에서 표가 갈리면 그 자리에서 다시 투표할 수 있습니다.
판이 끝나면 **한 판 더**로 이어 갈 수 있고, 새 제시어와 새 라이어로 다시 시작하면서
시민과 라이어의 전적이 쌓입니다.

## 술래 정하기

술래나 순서를 정할 때 쓰는 도구입니다. 뽑을 인원은 1명에서 3명까지 고를 수 있습니다.

### 손가락으로 뽑기

다 같이 화면에 손가락을 하나씩 올리고 그대로 기다리면, 셋을 센 뒤에 한 명을 뽑습니다.
손가락마다 색이 다른 동그라미가 붙어서 몇 명이 올렸는지 바로 보입니다.
중간에 손가락을 더 올리거나 떼면 처음부터 다시 셉니다.
뽑고 나면 손을 떼도 결과가 남아 있고, 다시 손가락을 올리면 새로 시작합니다.

여러 손가락을 동시에 인식해야 해서 **화면이 넓은 아이패드나 태블릿에서 쓰기 좋습니다.**

### 이름으로 뽑기

이름을 넣어 두고 뽑습니다. 휴대폰처럼 화면이 좁을 때나, 자리에 없는 사람까지 넣고
뽑아야 할 때 씁니다. 넣어 둔 이름은 다음에 열어도 그대로 남아 있습니다.

## 제시어

기본 제시어 **1186개**가 들어 있습니다. 주제 10개에 난이도 2단계이고,
제시어마다 힌트가 2~3개씩 붙어 있습니다.

| 주제 | 쉬움 | 어려움 |
|---|---|---|
| 동물, 음식, 스포츠, 직업, 인물, 사물·학용품, 장소, 행동·동작, 만화·캐릭터 | 60 | 60 |
| 감정 | 46 | 60 |

### 같은 제시어가 겹치지 않는 방식

게임을 시작할 때 조건에 맞는 제시어를 **전부 가져와 섞어 두고 앞에서부터 한 장씩** 꺼내 씁니다.
팀이나 사람이 바뀌어도 이 묶음이 이어지므로, 앞 팀이 쓴 제시어가 다음 팀에 다시 나오지 않습니다.

판이 끝나면 그 판에 나온 제시어를 기억해 두었다가 다음 판에서 뒤로 미룹니다.
그래서 같은 날 두 판, 세 판을 연달아 해도 앞판 제시어가 잘 나오지 않습니다.
이 기록은 설정 화면에서 지울 수 있습니다.

### 제시어 관리

홈 화면의 **제시어 관리**에서 다음을 할 수 있습니다.

- 주제별로 목록을 보고, 제시어와 힌트 내용까지 검색
- 제시어 추가, 수정, 삭제 (주제와 난이도, 힌트 3개까지)
- 한 줄에 하나씩 붙여넣어 **여러 개 한 번에 넣기** (이미 있는 것은 자동으로 제외)
- **내 주제 만들기** (예: 우리 반 친구들, 요즘 유행하는 것)
- 기본 제시어만 처음으로 되돌리기 (직접 만든 것은 그대로 남습니다)
- **JSON 파일로 내보내기와 가져오기** (다른 아이패드로 옮기거나 백업할 때)

## 개발

```bash
npm install
npm run dev
```

빌드는 다음과 같이 합니다. 결과물은 `dist/` 폴더에 생깁니다.

```bash
npm run build
```

`base`를 상대 경로로 잡아 두었기 때문에 `dist/` 폴더를 그대로 어디에 올리든 동작합니다.
GitHub Pages처럼 `https://아이디.github.io/저장소이름/` 같은 하위 경로에 올려도 됩니다.

### GitHub Pages에 올리기

`.github/workflows/deploy.yml`이 들어 있어서, **main 브랜치에 올리기만 하면 자동으로**
빌드하고 배포합니다. 처음 한 번만 아래를 해 두면 됩니다.

1. GitHub에서 빈 저장소를 만듭니다. Pages를 무료로 쓰려면 **공개(public)** 저장소여야 합니다.
2. 이 폴더를 그 저장소에 올립니다.

   ```bash
   git remote add origin https://github.com/아이디/저장소이름.git
   git push -u origin main
   ```

3. 저장소 **Settings → Pages → Source**를 **GitHub Actions**로 바꿉니다.
4. Actions 탭에서 배포가 끝나면 `https://아이디.github.io/저장소이름/` 으로 열립니다.
5. 아이패드 사파리로 그 주소를 열고 위의 **아이패드에 설치하기**를 따라 합니다.

그다음부터는 고친 내용을 `git push` 하기만 하면 몇 분 뒤 자동으로 반영됩니다.
아이패드에서는 앱을 껐다가 두 번 열면 새 버전으로 바뀝니다.

### 제시어 데이터 점검

제시어를 고치거나 늘린 뒤에는 아래 스크립트로 확인합니다.

```bash
npm run check:words
```

개수와 함께 다음을 검사합니다.

- **힌트에 정답이 새는지** (제시어의 두 글자 조각이 힌트에 들어가면 걸립니다)
- 제시어 중복, id 중복, 힌트 개수(2~3개), 금지 문자

이 점검은 배포할 때도 자동으로 돌아가서, 문제가 있으면 배포가 멈춥니다.

| 명령 | 확인하는 것 |
|---|---|
| `npm run check:words` | 전체 제시어 데이터 |
| `npm run check:one 동물` | 한 주제만 |
| `npm run check:game` | 한 판 안에서 제시어가 겹치는지 |
| `npm run check:repeat` | 연달아 여러 판을 했을 때 앞판 제시어가 다시 나오는지 |

## 저장되는 것

전부 아이패드 안(localStorage)에만 저장되고 밖으로 나가지 않습니다.

| 키 | 내용 |
|---|---|
| `charades.words` | 제시어 목록 |
| `charades.categories` | 주제 목록 |
| `charades.settings` | 소리 설정, 마지막에 쓴 게임 설정 |
| `charades.lastGame` | 진행 중이던 몸으로 말해요 게임 (새로고침해도 이어서 할 수 있게) |
| `charades.liarGame` | 진행 중이던 라이어 게임 |
| `charades.recentWords` | 지난 판에 나온 제시어 |

## 만들어진 기술

Vite + React + TypeScript, Tailwind CSS, vite-plugin-pwa.
효과음은 오디오 파일 없이 Web Audio API로 그때그때 만들어 냅니다.
